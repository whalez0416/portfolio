# 디자인 탐색 기록

게임을 등 뒤 시점(템플 런식)으로 다시 만들기로 하고, **코드를 쓰기 전에 그림을 먼저 정하기 위해** 만든 파일들입니다.
전부 브라우저로 그냥 열면 렌더됩니다. 빌드도 서버도 필요 없습니다.

이전까지의 순서가 거꾸로였습니다 — 로직을 만들고 화면은 코드가 그리다 나온 결과였습니다.
그래서 두 번 "이게 아닌데"가 나왔고, 두 번 다 메커니즘이 아니라 그림 문제였습니다.

| 파일 | 무엇 |
|---|---|
| `01-directions.html` | 같은 장면을 세 화풍으로. **B(계측 그리드)로 확정** |
| `02-figure-cycle.html` | 달리는 뒷모습 8단계 사이클 시트. 큰 크기와 실제 게임 크기를 같이 봄 |
| `03-runner-frame.html` | 확정된 인물 + 방향 B + 큰 글자 처리를 합친 프레임 |

## 확정된 것

**화풍 B — 계측 그리드.** 도로가 눈금이 있는 계측 표면입니다. 앰버 지평선 한 줄.
A(실루엣)와 C(안개)는 예뻤지만 "밤에 실루엣 러너"는 흔합니다.
B는 "당신은 계측기 위를 달리고 있다"는 이 포트폴리오의 명제 그 자체라 다른 게임일 수 없습니다.

**인물 — 뒷모습 달리기.** 두 번 실패하고 세 번째에 읽히기 시작했습니다.

1. 두 다리에 `0.5 - 0.5·sin(p)`를 π 위상차로 주면 `t=0`과 `t=0.5`에서 완전히 겹칩니다. 8단계가 다 똑같아 보였습니다.
2. 비대칭 사이클로 바꾸고 2본 IK를 썼더니, 다리가 접혀 엉덩이–발목 거리가 짧아질 때 **IK가 무릎을 신장의 1/4만큼 옆으로 날려** 캉캉 발차기가 됐습니다.
3. IK를 버렸습니다. 뒤에서 보면 접힌 무릎은 옆이 아니라 화면 안쪽으로 가고, 그건 **단축돼서 짧아 보이는 것**이지 옆으로 뻗는 게 아닙니다. 관절을 직접 배치하고 가로 이동을 아주 작게 묶었습니다.

**뒤에서 읽히는 단서는 따로 있습니다** — 뒤꿈치가 엉덩이로 차올라가는 것, 무릎이 들리는 것,
어깨와 골반의 역회전, 팔꿈치가 벌어지는 것, 상하 바운스. 옆모습 사이클을 뒤에서 본 것처럼 그리면 서 있는 것처럼 보입니다.

**크기 계산은 반드시 월드 단위로.** `p.s / F * 40` 같은 식은 가까울수록 폭발해서
제일 앞 가로등이 풍선만 해집니다. `월드크기 × p.s`로 쓸 것.

**큰 글자.** 한 번에 한 줄, 짧게. 캔버스가 아니라 DOM 오버레이로 얹습니다(폰트·접근성).
문장은 전부 짧게 다시 씁니다 — "설치 장벽이 진짜 병목이라고 봤습니다..." 대신 **"안 보이면 증명할 수 없다"**.
