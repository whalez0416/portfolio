# 게임 기획서

이 문서는 **게임이 어떻게 돌아가는가**를 적습니다.
이게 없어서 한 번 사고가 났습니다 — 서사만 보고 옛날 엔진에 얹는 바람에
확정된 시점(등 뒤)이 반영되지 않은 채로 커밋이 여덟 개 올라갔습니다.

그리고 **같은 사고가 미술 층에서 한 번 더 났습니다.** 사막·유적·인물·후처리 21커밋이
전부 `docs/design/04-journey-3d.html`(프로토타입)에만 들어가고 `index.html`은 24커밋 동안
손대지 않은 채였습니다. 코드는 있고 푸시도 됐는데 포트폴리오를 열면 옛 화면이 나왔습니다.
**프로토타입에서 확정한 것은 반드시 `index.html`까지 옮기고, 이 문서를 같이 고치세요.**
지금은 옮겨져 있고, 이 문서는 옮겨진 뒤의 상태를 적은 것입니다.

## 문서 순서

| 순서 | 문서 | 무엇을 정하나 |
|---|---|---|
| 1 | `docs/narrative.md` | **무슨 이야기인가.** 열 장면, 화면에 뜰 문장 |
| 2 | `docs/programs.md` | 문 여덟 개 안에서 무슨 말을 하나 |
| 3 | `docs/design/` | **어떻게 보이나.** 화풍 B, 인물 러닝 사이클 |
| 4 | **이 문서** | **어떻게 돌아가나.** 시점·조작·배치·규칙 |
| 5 | `index.html` | 코드 |

**위에서 아래로만 흐릅니다.** 코드가 문서를 이기지 않습니다.
이 문서와 코드가 다르면 코드가 틀린 겁니다.

## 한 줄

> **등 뒤에서 보는 시점 하나로 사막을 걸어 지평선의 산까지 갑니다.
> 길이 제 12년이고, 모래에 반쯤 묻힌 유적 여덟이 제가 만든 것들입니다.**

**정해진 길이 없는 3D 사막을 직접 걷습니다.** 오토러너가 아닙니다 —
자동 이동은 멀미의 첫 번째 원인이라 걷어냈고(`4ef8597`), 대신 방향을
지평선의 산이 줍니다. 트인 사막이라야 "어디로 갈지"가 실제로 내 선택이 됩니다.

렌더러는 **WebGL2**이고 의존성은 여전히 0입니다 — WebGL2는 라이브러리가 아니라
브라우저 기본 기능이고, 텍스처도 모델도 외부 파일이 아니라 전부 코드에서 만듭니다.

## 1. 시점 — 확정, 그리고 절대 바뀌지 않음

**등 뒤에서 보는 3인칭 원근 시점 하나.** 처음부터 끝까지.

이전 버전은 1~5장을 위에서 내려다보다가 갈림길에서 옆으로 눕혔습니다.
**두 개의 게임처럼 느껴진다**는 이유로 폐기됐습니다. 다시 만들지 마세요.

평면 투영이 아니라 진짜 3D 카메라입니다. **화각 44도 · 근평면 1.2 · 원평면 2400 ·
등 뒤 거리 7.8 · 눈높이 3.0.**

어지럽지 않게 만드는 일이 이 절의 전부입니다. 넷 다 실제 멀미를 고친 것들입니다:

- **지형을 1:1로 따라가지 않습니다.** 앞쪽 다섯 지점의 평균 높이(`groundAvg`)를
  천천히 좇습니다. 1:1이면 언덕마다 카메라가 위아래로 채질을 합니다.
- **시선은 인물이 아니라 앞쪽 16 단위의 한 점**을 봅니다. 그래야 지평선이 안 출렁입니다.
- **화각을 52도에서 44도로 좁혔습니다.** 넓은 화각은 주변부가 빨리 흘러서 그 자체로 멀미입니다.
- **방향 전환도 카메라가 조금 늦게 따라옵니다**(`3.0/s`).

지형 격자는 **일정 간격(2.2)** 이어야 하고 카메라 위치를 칸 단위로 **스냅**해야 합니다.
등급 격자(멀수록 성기게)를 쓰면 칸에 스냅할 수가 없고, 그러면 정점이 매 프레임 지형 위를
미끄러집니다. 플랫셰이딩이라 그 미끄러짐이 화면 전체의 면을 계속 갈아치우고, 바닥이
잘게 기어다닙니다 — 어지러움의 제일 큰 원인이었습니다.

**격자는 카메라 뒤로도 200 단위 깔립니다**(`ZBACK`). 40이었을 때는 뒤를 돌아본 순간
지형이 끊겨 지나온 유적들이 하늘에 떠 보였습니다. 앞만 보고 걸을 때는 안 드러나는데,
유적에서 나올 때마다 뒤를 보게 되므로 실제로는 매번 보입니다.

## 2. 조작 — 두 개뿐

| 키 | 하는 일 | 언제부터 |
|---|---|---|
| `↑` | 걷기 | 처음부터 |
| `←` `→` | 방향 | 처음부터 |
| `Enter` / 앰버 버튼 탭 | 유적에 들어가기 | 유적 앞(16 안쪽), 선택 |
| `Esc` `Enter` | 나오기 | 유적 안 |

**점프 없음. 발행 없음.** 손가락으로 할 일은 걷기와 방향 둘뿐입니다.
문지방을 넘으면 Enter 없이도 그냥 들어가집니다 — 문 앞에서 키를 누르는 건
"읽으시겠습니까"이고, 문지방을 넘는 건 이미 대답입니다.

터치는 `◀ ▶ ▲걷기` 세 버튼. **어느 것도 비활성화하지 마세요** — 예전에 조작을
막았다가 터치 사용자가 영구히 갇힌 적이 있습니다.

**캔버스에 `tabindex`가 있어야 합니다.** 없으면 `canvas.focus()`가 아무 일도 안 하고
키 이벤트가 게임에 영영 도달하지 않습니다 — 마우스로 시작 버튼을 누른 뒤 키보드로는
한 걸음도 못 걷는 상태로 나갑니다. 실제로 그렇게 한 번 나갔고 `test/a11y.js`가 잡습니다.
유적에 들어가면 포커스가 닫기 버튼으로 넘어가므로, **나가는 키는 패널에도 붙어 있어야**
합니다. 안 그러면 들어간 채로 갇힙니다.

## 3. 실패가 없습니다

죽지 않고, 리셋이 없고, 점수로 지지 않습니다. 막는 벽도 없습니다 —
사막은 트여 있고 어디로든 걸어갈 수 있습니다.

몸으로 막히는 것은 **유적의 돌**뿐이고, 그것도 벽을 따라 미끄러집니다(축을 나눠 풀어서).
막힌 채로 서 버리면 벽에 붙을 때마다 걸음이 뚝 끊깁니다.

자기소개라서 그렇습니다. 못 보고 끝나는 이력서는 이력서가 아닙니다.

## 4. 길 · 문 · 기록 — 섞지 않습니다

| | 무엇 | 출처 | 강제되나 |
|---|---|---|---|
| **길** | 서사. 달리면 열 장면이 흐름 | `docs/narrative.md` | 강제 |
| **문** | 프로그램. 만든 이유·막힌 곳 | `docs/programs.md` | **선택** |
| **기록** | 사실. 수치와 스택 | `index.html`의 `.rec` 한 벌 | 아래 본문 |

- 길에서는 멈추지 않습니다. 문 안에서는 조작을 요구하지 않습니다 — 거긴 읽는 자리입니다.
- **문을 하나도 안 열고 끝까지 달려도 이력은 완결됩니다.**
- 게임 안에 프로젝트 설명을 **복제하지 마세요.** `RECS` 인덱스로 `.rec`을 꺼내 씁니다.

## 5. 배치 — 이 표가 유일한 출처

산은 `(14, 440)`에 못박혀 있고 속도는 4.6입니다. 진행도는 시간도 걸음 수도 아니라
**"산 쪽으로 얼마나 나아갔는가"(z 최고점)** 입니다. 사막에는 정해진 길이 없어서
거리로 재면 옆으로 헤맨 것까지 이야기가 앞서 나가고, z로 재면 이야기와 지형이 붙습니다.

### 절대 건드리지 말 것 — 랜턴은 여섯 번째

7개월입니다. 여섯 번째 유적에서 **나오는 순간** 사막 전체에 티끌이 떠오르고
"그동안, 계속 읽히고 있었습니다 — 셀 방법이 없었을 뿐입니다"가 뜹니다.
그 순간이 이 게임의 전부입니다. 앞으로 당기면 8장이 통째로 무너집니다.
`?selftest`와 `test/walk.js`가 이 순서를 검사합니다.

나오는 자리는 문 앞 **18** 단위입니다. 8.4로 세우면 등 뒤 7.8의 카메라가 유적 안에
박혀서 화면 절반이 벽이 됩니다 — 하필 랜턴이 켜지는 장면이 거기입니다.

## 6. 캐릭터

### 주인공 = 최희준

도구를 의인화한 게 아닙니다. 플레이어가 조작하는 사람이 곧 저입니다.
화면 문장이 전부 1인칭인 것도 여기서 나옵니다 — "이 도구는 ~합니다"가 아니라 "저는 ~했습니다".

### 뒷모습이라 못 쓰는 것

**안경 · 표정 · 얼굴 · 재킷 앞면 · 정면 실루엣.** 전부 사람의 반대쪽에 있습니다.
예전 픽셀 버전의 안경(앰버)·가방(블루)·재킷(아이보리)은 옆모습 기준이라 그대로는 못 씁니다.

### 뒤에서 읽히는 것 — 이것만 씁니다

| 단서 | 어떻게 쓰나 |
|---|---|
| **가방** | 등 한가운데. 뒤에서 정체성을 나를 수 있는 유일한 실루엣 |
| **손에 든 것** | 여섯 번째 문 이후 램프. 팔 스윙을 따라 흔들림 |
| **림라이트** | 왼쪽 가장자리에 앰버 한 줄. 나만 있음 |
| **달리는 폼** | 뒤꿈치 차올림 · 무릎 들림 · 어깨/골반 역회전 · 팔꿈치 벌어짐 · 상하 바운스 |

옆모습 사이클을 뒤에서 본 것처럼 그리면 **서 있는 것처럼 보입니다.**
앞뒤 보폭은 뒤에서 보면 정면이라 안 보입니다. (`docs/design/README.md`에 실패 두 번 기록)

### 확정된 캐릭터 시트

```
주인공   실루엣 #080A10 · 왼쪽 림라이트 rgba(255,190,90,1)
         + 백팩(앰버 테두리 rgba(255,174,26,.62), 뚜껑 이음선 한 줄)
         + 램프(여섯 번째 문 이후, 오른손)
무리     실루엣 #39415C · 림라이트 없음 · 가방 없음 · 램프 없음
키       1.75 월드 단위 (양쪽 동일)
```

**두 사람의 유일한 차이는 가방입니다.** 같은 릭, 같은 실루엣, 같은 폼.
한 사람만 뭔가를 지고 있습니다.

### 가방이 성장 곡선입니다

문을 지날 때마다 가방이 커집니다 — `0.18 → 1.0`, 문 8개에 걸쳐서.
**성장이 UI 숫자가 아니라 실루엣에 보이는 게 요점입니다.**
1장에서 아무것도 못 하는 것과, 10장에서 등이 무거운 것이 같은 그림의 양 끝입니다.

무리는 끝까지 빈손입니다. 그게 5장입니다.

### 아직 안 정한 것

- **얼굴을 한 번이라도 보여줄 것인가** (엔딩에서 돌아본다든지). 지금은 안 보여줍니다.
- 가방 안에 뭐가 들었는지 보여줄 것인가 (열린 문 8개 = 8개의 무엇).
- 램프 외에 손에 드는 것을 더 늘릴 것인가.

## 7. 월드 구성물

| 물건 | 무슨 뜻인가 | 규칙 |
|---|---|---|
| **사막** | 정해진 길이 없다는 것 | 높이 함수가 GLSL 문자열 한 벌. CPU와 셰이더가 **같은 식**을 씁니다 |
| **등성이** | 저니 사막의 초승달 능선 | `1-|sin|` — 마루가 접혀서 플랫셰이딩이 칼 같은 빛/그늘 경계를 만듭니다 |
| **무리** | 노출을 팔던 사람들 | 회색 로브. 5장 자막 지점에서 **2초 안에 전원이 꺾고, 한 명이 멈춰 돌아봅니다** |
| **유적 8** | 프로그램 8개 | 모래에 반쯤 묻힘(−1.1). 세월에 살짝 기욺 — **반듯한 유적은 신축 건물** |
| **문간의 빛** | "저기 뭔가 있다" | 스스로 빛나는 면. 빛 계산을 태우면 그냥 어두운 구멍이 돼 멀리서 안 걸립니다 |
| **깃발** | 유적의 표식 | 로브와 같은 적 가족, 조금 바램 |
| **앰버 티끌** | **크롤러(AI 봇)** | **랜턴 전에는 아예 없습니다.** 여섯 번째를 나오는 순간 사막 전체에 떠오릅니다 |
| **빈 문틀** | Price Lock. 만들어 놓고 지움 | 지나갈 수는 있지만 **아무 데로도 이어지지 않습니다** |
| **산** | 목표. 방향은 이것이 줍니다 | 월드에 못박힘. 안개를 거의 안 먹여 **뿌옇지만 절대 안 사라집니다** |
| **나침반** | 유적에서 나오면 방향을 잃습니다 | 진행 방향이 늘 위. 표기는 셋뿐 — 산(침) · 유적(점, 가본 곳은 빈 원) · 나 |
| **긴 노을 그림자** | 해가 지평선에 걸려 있다는 것 | 최대 24개. 없으면 사람도 유적도 전부 스티커로 보입니다 |

**티끌 규칙이 이 게임의 인과 그 자체입니다** — 그동안에도 계속 지나다니고 있었는데,
이제야 보이는 것들.

## 8. 화면 문장

- **저니식 자막.** 화면 가운데, 얇게, 자간 넓게, 2.6초에 걸쳐 나타났다 사라집니다.
  캔버스가 아니라 **DOM 오버레이**입니다(폰트·접근성).
- **한 비트에 2~3줄이 연쇄됩니다: 상황 → 그래서 → 결과.** 결론만 한 줄씩 떨어뜨렸더니
  "스토리텔링이 뭐라는지 모르겠다"가 됐습니다 — 당연합니다, 문단을 안 읽은 사람에게는
  주어도 맥락도 없었으니까.
- 빨리 걸어 비트를 여럿 건너뛰면 **최신 것만 남깁니다.** 대사가 위치를 세 비트씩
  뒤따라오면 그게 또 다른 "무슨 말인지 모르겠다"입니다.
- **유적 안에서는 자막이 흐르지 않습니다.** 거긴 읽는 자리라 겹치면 둘 다 죽습니다.
- **`docs/narrative.md`에 없는 문장은 화면에 없습니다.** 필요하면 거기에 먼저 씁니다.

## 9. 소리 · 접근성

- 오실레이터 블립 셋(문·랜턴·엔딩), 파일 없음. **기본 꺼짐** — 예고 없이 소리 내는 이력서는 실례입니다.
- `prefers-reduced-motion`을 지키면 전환이 꺼집니다.
- 진행은 `#jn-live`(`aria-live=polite`)로 안내합니다. 같은 내용이 아래 본문에 전부 글로 있습니다.
- 터치 패드는 `aria-hidden` 안에 두지 마세요 — 포커스 가능한 요소가 들어가면 WCAG 4.1.2 위반입니다.
- **캔버스는 `tabindex="0"`** 이라야 합니다(2절). 없으면 키보드 사용자가 게임을 못 합니다.
- 유적 안의 본문은 `RECS`로 `.rec` 한 벌을 꺼내 씁니다 — 스크린리더에게도 같은 글입니다.
- **WebGL2가 없으면** 그림만 빠지고 게임 로직과 안내는 그대로 돕니다. 페이지가 깨지지 않습니다.

## 10. 검증

넷이 서로 다른 종류의 실패를 잡습니다. **하나로 합치지 마세요.**

```
?selftest                # 상수·배치·순서          — 걸어보지는 않는다
node test/walk.js        # 끝까지 갈 수 있는가      — 화면은 보지 않는다
node test/a11y.js        # 진짜 브라우저에서 잰다   — 그림은 판단 못 한다
node test/shoot.js       # 그림을 찍어서 눈으로 본다
```

`?selftest`가 지키는 것: **랜턴이 여섯 번째인가** · 유적이 만든 순서(z)대로 놓였는가 ·
유적 이름이 실제 기록(`.rec`)과 맞는가 · 문마다 "왜 만들었나"가 있는가 ·
대본이 산 쪽으로만 흐르는가 · 빈 문틀이 NetTier와 Hospify 사이인가 · 산이 마지막 유적보다 먼가.

`?selftest`는 검사 창구(`window.JOURNEY`)도 엽니다 — 사막은 정해진 길이 없어서 여덟 유적을
걸어 도는 데만 몇 분이라, 문 앞까지는 순간이동으로 데려다 놓고 **들어가고 나오는 것만 진짜로**
시킵니다. 잡으려는 건 이동이 아니라 문과 이야기입니다.

**브라우저 검사가 실제로 잡은 것** (이식하면서 넷 다 실제로 났습니다):

- 캔버스에 `tabindex`가 없어 **키보드로 한 걸음도 못 걷던 것** — 마우스로 시작 버튼을
  누르면 포커스가 캔버스로 못 가고, 그 뒤로 키가 게임에 영영 도달하지 않았습니다.
- 유적에 들어가면 포커스가 닫기 버튼으로 넘어가 **Esc가 안 먹고 갇히던 것.**
- 유적에서 나오는 자리가 8.4라 **카메라가 벽 안에 박히던 것** — 하필 랜턴 장면이 거기입니다.
- 뒤를 돌아보면 지형이 끊겨 **지나온 유적들이 하늘에 떠 보이던 것**(`ZBACK` 40 → 200).

**`shoot.js`가 없으면 그림 문제는 절대 안 잡힙니다.** 다만 WebGL 캔버스는
`preserveDrawingBuffer` 없이 `drawImage`로 읽으면 늘 비어 나오므로, **픽셀을 직접 세면
언제나 "검은 화면"이라고 거짓말합니다.** 찍힌 PNG의 크기로 봅니다 — 단색은 몇 KB,
사막은 수백 KB입니다.
